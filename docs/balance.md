# 육성 밸런스 기준과 재현

사용자 선택: **표준 육성형, 선택과 집중이 중요**. 기본 편성으로 한 해를 버틸 수 있고, 특정 전형의 좋은 결과를 노리면 다른 능력·시간·재화를 포기하도록 조정합니다. 모든 성과를 동시에 최고로 만드는 기본 편성을 목표로 하지 않습니다.

## 현재 기준 — 2026.10.28-3

종합 전형에서 학점·학교생활기록이 65~70%를 차지합니다. 논문은 기록의 한 활동이고, 기존 교과 과제도 탐구에 기여합니다. 방향 선택의 즉시 점수 보너스를 없애고 지원할 전형의 묶음으로 바꿨습니다. 제출 당시 자료는 보존하며 이후 면접은 별도로 반영합니다. `data/admissions.json`이 기록·관계 보조·전형 가중치를 설정합니다.

자소서의 기록/관계 부담은 선형이고 추천서도 같은 방식으로 상담당 체력0~3·집중력0~1.5·스트레스0~4를 추가 소비합니다. 차이가 큰 준비는 자원 부담으로 느끼게 하고 인접한 기록/관계는 작은 차이만 만듭니다. 추천서 기본2회 상담 후 다음 게임 날 검토가 끝나며, 기록이 낮다는 이유를 비난하는 문구는 없습니다. 형식 미지정 교과 과제의 탐구 기여0.5·형식 지정1·논문1.5는 품질을 곱하며 탐구 표본6에서 상한에 도달합니다. 논문 하나의 생기부 점수 기여는 최대5점입니다.

최신 70회 비교는 아래 검증 기록의 재현 명령으로 생성합니다. 상위 전형의 기준86은 유지했습니다. 별도 고정 시드4의 종합 집중 전체 플레이는 과로 피로 없이 상위 전형을 통과하는 회귀 검사로 두었습니다. 두 시드의 작은 표본에서 모든 전략이 최고 전형을 얻도록 맞추지 않습니다.

## 이전 변경 — 2026.10.27-8

변경 전 고정 시드 1107·수학·할 일 우선 편성은 41주 중 38주 피로, 체력·집중력 0, 스트레스 98인데도 주요 학업 능력은 모두 100, 2학기 학점 4.26이었습니다. 균형 편성은 과제 등록 순서 때문에 임박한 마감보다 장기 과제를 먼저 잡았습니다. 이는 플레이어가 기본 편성을 신뢰하기 어렵고 후반 선택의 가치도 사라지는 문제였습니다.

- 편성은 마감 순서로 처리하고 고정 수업·강연도 같은 주간 작업 예산에서 차감합니다. 보통 학습 9칸, 피로·낮은 체력·높은 스트레스 상태는 5칸을 기준으로 회복 활동을 사이에 둡니다. 플레이어가 직접 편집하는 칸 수를 제한하지는 않습니다.
- 공통 학업 능력·과목 이해도·평판·매력·교사 친밀도는 높은 값일수록 천천히 성장합니다. 캐릭터 특성의 시작 보너스는 그대로입니다.
- 초기 평가에는 단계적인 입문 보정이 있고 2학기부터 전체 평가 수준을 적용합니다. 퀴즈 20·중간 30·기말 30·수행 20의 비율은 유지합니다. 시험 난도·생활 피로·반복 효과도 남습니다.
- 두 예시 과제 모듈의 실수는 수행 점수를 완만하게 낮춥니다. 진행·마감·완료 조건은 모듈의 책임이며 현금 보상은 없습니다.
- 종합 전형의 기준은 전형별로 다릅니다. 상향 집중은 서울대·카이스트/포스텍 준비에 보너스, 고대 준비에 감점이 있고 안정 집중은 반대입니다. 선택 하나로 모든 학교의 기준을 낮추지 않습니다. 선택 창과 결과에 실제 보너스를 표시합니다. 이는 실제 입시 예측 모델이 아닙니다.
- 화면에 표시한 입시 점수로 합격 여부를 비교합니다. 반올림 전에는 불합격인데 화면 점수는 합격 기준과 같은 현상을 없앴습니다.
- 청소 미완료 벌점만 쌓였다는 이유로 감옥 결말을 강제하지 않습니다. 위험한 편법 선택과 누적 위반이 함께 있어야 합니다.

## 안전하게 조정하기

주요 설정은 `data/balance.json`, 성장 함수는 `src/domain/balance.js`, 편성은 `auto-plan.js`, 평가는 `grades.js`, 전략 비교는 `tools/simulation/`에 있습니다. 시험 점수 안내와 활동 효과 미리보기는 같은 계산 함수를 사용합니다. 설정의 유효 범위·가중치 합·알 수 없는 필드는 `npm run check`에서 검사합니다.

규칙 변경 시 CONTENT_VERSION을 올리고 전체 검사와 비교를 실행합니다. 이전 저장의 능력치·과제 진척·확정 성적·입시 결과를 새 공식으로 소급 계산하지 않습니다. 새 규칙은 이후의 행동에 적용됩니다. 과제 모듈을 고칠 때는 기존 모듈 ID와 저장 계약을 보존하고, 호환되지 않는 동작은 새 버전 ID로 등록합니다.
