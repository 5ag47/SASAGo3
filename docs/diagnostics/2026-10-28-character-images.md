# 시작 화면 두 번째 캐릭터 표시

사용자 증상: 두 번째 캐릭터가 비거나 깨져 보임. 캐릭터 선택은 새 게임에서만 허용하며 설정에서 변경하지 않는다.

## 확인한 사실

- ag_test와 최초 이미지 커밋09c4885, 현재 파일의 Git blob이 동일했다. 원본 이미지를 삭제하거나 다른 그림으로 대체한 이력은 없었다.
- 현재 로컬 서버의 두 원본 경로는 HTTP200·image/png이며 파일 내용도 원본과 같았다. 이미지 자체는 PNG 디코더로 읽혔다. 실제 사용자 브라우저의 캐시·디코딩·표시 중 어디서 실패했는지는 도구 제어 비활성 상태라 확정하지 못했다.
- 요청을 잘못 해석해 설정 변경을 잠시 구현했으나 사용자 정정 직후 화면과 서버 명령에서 제거했다. 해당 경로는 공개 배포하지 않았다.

## 수정

원본 두 장을 src/assets/characters/character-01.png·character-02.png로 바이트 그대로 복사해 ASCII 경로에 연결했다. SHA-256 원본/배포용 사본 일치: 01은8d47e264696fb21e9ed16c17d7372c104569c898dcb3e1b7604fd449f95edf86, 02는2ba891e1dfab44512cb9b48b124d302ca595b81f066d9cc0e0b68e26533c9155다. 그림·투명도는 변경하지 않았고 기존 원본 파일도 보존했다.

시작 화면 선택 컴포넌트를 분리해 각 이미지 URL이 다름을 확인했다. 로드 실패는 빈칸 대신 오류와 다시 불러오기를 표시한다. 재시도는 선택을 몰래 바꾸지 않으며 두 번째 선택 시 큰 미리보기도 같은 그림으로 바뀐다. UI·대체 텍스트에 성별 이름을 넣지 않는다.

기존 boy/girl 저장 ID를 보존하고 새 게임 생성 외 캐릭터 변경 API는 제공하지 않는다. 이후 변경 명령·재생성은 서버가 거절하고 저장의 캐릭터·revision을 유지하는 회귀 검사를 추가했다. 설정에 선택기가 없다는 React 검사도 추가했다. 기존 플레이어 기록은 초기화하지 않는다.

새 경로 배포 후 사용자가 ‘두 번째 캐릭터가 정상 표시됨’으로 응답했다. 해당 시작 화면의 표시 확인을 받았다. 최초 실패가 캐시·디코딩·전달 경로 중 어디에서 발생했는지는 확정하지 않는다.

2026.10.28-2 공개 배포 후 두 새 자산 URL을 query 재시도 경로로 직접 요청했다. 각각 HTTP200·image/png·원본 바이트 일치를 확인했다. 전체187개 검사와 보안 빌드가 통과했다. 설정 UI와 서버에서 캐릭터 변경 경로가 없음을 확인했다.
