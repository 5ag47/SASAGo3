# 진행·입력 지연 개편 추적

기준: 2026-10-28까지 이번 작업 중 들어온 사용자 요구 전체. 앞선 원본 기능·확장성·서버 검증·공동개발·프로토타입 질감 요구도 유지한다.

- 과제 풀이 후 다시 시간 배정·주간 완료를 요구하는 역순 제거. 계획한 시간에 실제 작업하고 성공한 작업은 즉시 반영한다.
- 사용자 선택: 주간 계획 후 자동 실행, 과제와 중요한 결과에서만 정지한다. 게임 속 다음날 스터디 지원 결과를 받는다.
- 장기 프로젝트는 여러 작업으로 나누고 도전마다 비용을 소비한다. 몰아서 수행하면 부담이 커지고 초반의 성공은 이후에 도움이 된다.
- 모듈마다 도전 비용·성공/실수 효과·반복 부담·초반 보너스를 설정하고 서버 난수를 사용한다. 동일 모듈의 여러 과제·그룹 사용과 독립 저장은 유지한다.
- 입력 즉시 반응. 점수·완료는 서버 검증. 묶음 제출·중간 저장·충돌·실패·새로고침 복구까지 검사한다.
- 튜토리얼의 자동 메뉴 열기 제거. 실제 버튼 위치를 안내하고 직접 조작한 결과로 판정한다. 다른 메뉴와 단원 순서를 잠그지 않는다.
- 주간 플레이 유지. 날짜·요일을 갖는 월간 달력에 날짜별 일정·마감·내 계획을 표시한다. 날짜가 미정인 일정은 확정된 날짜처럼 표시하지 않는다.
- 과제/달력 외에도 사용자가 예상하는 행동과 실제 결과가 어긋나는 흐름을 점검한다. 완료·저장·지원 중·작업 중을 같은 상태처럼 보이지 않게 한다.

## 재현

`node --test tests/ui/input-latency.test.js`: 저장 응답을 보류한 실제 React 과제 화면에서 첫 카드를 누르면 다음 카드까지 비활성화되어 실패한다. 타이머나 육안 판정에 기대지 않는 재현이다.

가설 순서: (1) 서버 응답 중 전역 busy가 모든 입력을 잠금, (2) 매 클릭 인증 조회·원자적 DB 저장·전체 상태 전송, (3) 후반 기록 크기에 따른 복사·갱신 비용. 입력·전송·도메인 처리 시간을 나눠 원인과 개선 결과를 기록한다.

## 원인과 수정

첫 카드의 저장 응답을 기다리는 동안 전역 busy가 다음 선택을 막았다. 재현 검사를 먼저 실패시킨 뒤, 선택 미리보기·220ms 입력 묶음·결과 확인 장벽으로 나눠 통과시켰다. 첫 요청이 진행 중이어도 다음 두 선택이 즉시 반영되는 실제 React 검사를 유지한다. 서버 결과·점수·과제 완료는 미리 확정하지 않는다.

후반 전체 기록 복사·전송도 비용을 키웠다. 미니게임 입력은 변경 가능한 상태만 복사하고 task-v1 응답으로 새 과제·스탯·실행 위치만 보낸다. 40주 기록 표본의 전체 상태 343,831바이트 대비 차이 응답 2,884바이트로 약99.2% 줄었다. 초기 재현의 CPU+직렬화 p95 7.69ms에서 최종 계측은 5.92ms, 중앙값은 6.15→3.89ms였다. 앞선 개편 계측의 p95는4.66ms로 기기 부하에 따라 변했다. Google 인증·D1·인터넷·실제 브라우저 체감 시간을 포함하지 않는다. `npm run perf:input`으로 재현하며 합성 기록만 .local/input-performance.json에 쓴다.

인증·Firebase 계정 폐기 확인을 생략하지 않았다. 작은 요청·연속 입력·불변 기록 공유로 지연을 줄였다. 응답 유실·중복·다른 창의 입력 충돌·임시 입력 복구 검사를 추가했고 이미 확정된 입력을 다시 반영하지 않는다.

## 흐름의 회귀 기준

- 배정 전 작업 시작은 거절하고, 배정한 시간의 성공은 즉시 진척/완료한다. 주간 종료까지 미루지 않는다.
- 재접속은 같은 칸·보드·이미 낸 비용을 유지한다. 명시적 중단은 진척 없이 종료하고 재도전에는 새 비용을 적용한다.
- 구버전 통과 퍼즐은 한 번만 완료로 변환하며 미완료 보드는 보존한다.
- 스터디 지원은 다음 게임 날짜에만 결과가 도착한다. 접수와 합류 상태를 구분한다.
- 논문 여러 회차·주간 상한·실패 효과·초반 보너스·시드 난수·다음 주 피로를 검사한다.
- 월간 달력의 윤년·월 경계·날짜별 계획·요일 지정 발생·기존 마감 스냅샷을 검사한다.
- 튜토리얼에서 직접 찾아보기를 눌러도 달력은 열리지 않는다. 실제 하단 버튼을 눌러야 관찰 기록이 생긴다.

## 실제 화면 확인의 한계

2026-10-28 cua_repl에서 현재 localhost 탭을 읽으려 했으나 ‘Local browser use is disabled in Work settings’가 반환되었다. 우회 조작은 하지 않았다. jsdom 조작 회귀·보안/편집기 빌드·합성 성능 계측은 수행했지만 새 달력·안내 강조의 실제 배치·작은 화면·사용자 체감 반응은 추가 확인해야 한다. 이전 버전의 사용자 로그인·저장 성공 기록을 이번 개편의 확인으로 취급하지 않는다.

공개 개편판 배포 후 작업 진행·완료·새로고침 유지·연속 입력을 확인하도록 요청했고, 사용자가 ‘진행·저장·입력 반응 모두 정상’으로 응답했다. 이 경로의 사용자 확인을 받았으며 모든 기기에서의 배치·초보자 관찰까지 확인한 것으로 확대하지 않는다.
