# 과제·미니게임 모듈·그룹 편집

과제 내용은 `data/assignments.json`, 플레이 규칙은 `src/domain/task-modules`, 미니게임 화면은 `src/features/year-game/task-games`에 있습니다. 기존 과제 94개의 ID·일정·분량·효과를 옮겼으며 새 과제 내용을 추가하지 않았습니다. 과목별 평가 비율도 유지합니다.

## 로컬 편집기 사용

1. GitHub Desktop에서 SASAGo3 저장소를 선택하고 현재 브랜치가 `codex/sasago3-web-game`인지 확인합니다. 새 브랜치를 만들지 않습니다.
2. 이 프로젝트의 터미널에서 `npm run tasks:editor`를 실행합니다. 프로젝트 경로는 `C:\Users\retet\OneDrive\Documents\Github\unity-practice\unity-project\SASAGo3`입니다.
3. 브라우저에서 `http://127.0.0.1:5182/`를 엽니다. 공개 게임과 별도인 로컬 편집기입니다. 로그인이나 플레이어 저장 접근은 없습니다.
4. 왼쪽에서 기존 과제를 선택하면 이름·설명·과목·일정·분량·단계·완료/미완료 효과를 바꿀 수 있습니다. 기존 ID는 바꾸지 않습니다.
5. 새 과제가 필요하면 ‘새 과제·그룹 ID’에 영문 ID를 입력하고 ‘빈 과제 만들기’를 누릅니다. 이름과 내용을 직접 입력합니다. 이 작업만으로 게임 파일이 바뀌지는 않습니다.
6. ‘처리 모듈’에서 순서 정리 또는 패턴 기억을 선택합니다. 비워 두면 그룹 설정을 따릅니다. 과목 과제의 기본값은 순서 정리, 공통 과제는 패턴 기억입니다. 첫 주 수학 실습은 순서 정리를 사용합니다.
7. 여러 과제를 묶으려면 ‘그룹 만들기’를 누르고 그룹 이름·모듈을 정한 뒤 묶을 과제를 체크합니다. 과제에 직접 지정한 모듈이 그룹보다 우선합니다. 서로 다른 그룹의 모듈 설정이 충돌하면 입력 문제로 표시합니다.
8. 입력 문제가 0개가 되면 ‘변경 N개 내보내기’를 누릅니다. 다운로드 폴더에 `sasago3-task-changes.json`이 생깁니다. 과제 목록 전체가 아니라 변경한 항목과 편집 전 값만 포함합니다.
9. 터미널에서 아래 명령을 실행합니다. 파일을 다른 위치에 받았다면 따옴표 안의 경로만 실제 위치로 바꿉니다.

```powershell
npm run tasks:apply -- "C:\Users\retet\Downloads\sasago3-task-changes.json"
npm run check
npm test
```

10. 성공하면 GitHub Desktop의 Changes에서 `data/assignments.json`의 변경을 확인합니다. 공개 게임 반영은 보안 빌드와 배포가 필요하며 로컬 편집만으로 공개 서버가 바뀌지 않습니다.

다른 사람이 다른 과제를 수정했다면 그 내용을 보존하고 합칩니다. 같은 항목이 편집 전 값과 다르면 해당 ID를 표시하고 전체 적용을 중단합니다. 최신 내용을 다시 연 뒤 자신의 변경을 비교해 적용하세요. 강제 덮어쓰기는 없습니다. 적용 전 파일은 `.local/task-edit-backups`에 백업합니다. 적용 작업끼리는 잠금 파일로 직렬화합니다. 외부 편집기와 Git의 모든 동시 변경까지 방지한다고 보장하지는 않습니다.

## 실제 플레이 흐름

- 할 일에서 ‘미니게임 시작’을 누릅니다. 순서 정리는 숫자 네 개를 오름차순으로 고르고, 패턴 기억은 네 칸을 기억해 다시 고릅니다. 제한 시간은 없습니다.
- 행동마다 서버가 검증하고 과제별 진행을 저장합니다. 창을 닫거나 새로고침해도 이어집니다. 같은 모듈을 쓰는 두 과제의 진행은 공유하지 않습니다.
- 예시 모듈은 미니게임 통과와 자습시간 투자를 모두 요구합니다. 준비와 시간 배정 순서는 자유롭습니다. 통과하지 않은 과제는 배정해도 진척이 오르지 않으며 주간 검토에 표시됩니다.
- 통과 후 배정한 시간은 원래 과제의 진척도를 채웁니다. 목표에 도달하면 자동 완료합니다. 클릭만으로 완료시키거나 현금을 지급하지 않습니다.
- 반복 과제는 각 발생 주별로 별도 ID와 미니게임 상태를 가집니다. 단계는 전체 진척도를 나누어 표시하며 완료 효과는 전체 과제당 한 번만 적용됩니다.

## 코드로 새 모듈 추가

1. `src/domain/task-modules/order-v1.js` 또는 `pattern-v1.js`를 새 파일로 복사합니다. 파일과 모듈 ID에 새 이름·버전을 붙입니다. 기존 버전의 동작을 바꾸거나 삭제하지 않습니다.
2. 같은 화면을 재사용할 수도 있고 새 화면을 만들 수도 있습니다. 새 화면이면 `src/features/year-game/task-games`에 React 파일을 만들고 `registry.jsx` 및 `catalog.js`에 화면 ID를 등록합니다.
3. 도메인 모듈을 `src/domain/task-modules/registry.js`의 작은 등록 목록에 추가합니다. 중복 ID와 빠진 필수 함수를 검사합니다.
4. 편집기를 다시 열면 등록한 미니게임 모듈을 선택할 수 있습니다. 특정 과제에만 지정하거나 그룹에 연결합니다.
5. 새 모듈의 성공·실패·중간 저장·잘못된 입력·재전송 사례를 테스트하고 검사·빌드를 실행합니다.

게임 데이터에는 실행 코드나 파일 경로를 넣지 않습니다. 등록된 모듈 ID와 설정만 사용합니다. 모듈 코드는 개발자가 저장소에 추가하고 검토·배포합니다. 웹 플레이어가 보낸 JavaScript나 점수를 실행·신뢰하지 않습니다.

## 모듈 계약

| 함수/필드                              | 책임                                                         |
| -------------------------------------- | ------------------------------------------------------------ |
| `id`, `name`, `unit`, `estimated`      | 버전이 있는 ID, 표시 이름, 진척 단위, 시간 추정 여부         |
| `validate(params)`                     | 설정 오류 문자열 배열. 정상은 빈 배열                        |
| `work(context)`                        | 시간 투자 시 진척 증가량과 선택적 `data` 반환                |
| `isComplete(context)`                  | 완료 조건. 시간 처리와 미니게임 행동 후 공통으로 검사        |
| `estimate(context)`                    | 남은 예상 자습 칸 수. 프리셋과 주간 검토에서 공유            |
| `complete(context)`, `expire(context)` | 점수 또는 null, 능력치 효과, 선택적 결과 메모·수상 횟수 반환 |
| `game.view`, `game.instructions`       | 화면 등록 ID와 시작 안내                                     |
| `game.create(context)`                 | 최초 미니게임 상태 생성                                      |
| `game.act(context, data, action)`      | 행동 검증 후 새 상태 반환                                    |
| `game.valid(data)`                     | 저장·복구 상태 검사                                          |
| `game.public(data)`                    | 클라이언트에 보여 줄 상태. 패턴 정답은 입력 단계에서 숨김    |

`context`는 과제 스냅샷, 능력치, 모듈 설정, 과목 실력, 저장 난수를 사용하는 `roll()` 등을 제공합니다. 원본 상태를 직접 고치지 않고 결과를 반환합니다. 미니게임 상태는 과제의 `moduleData`에 저장하며 JSON 값, 깊이·항목 수·문자열 길이를 제한합니다. 두 예시는 `passed`로 통과 여부, `phase`로 진행 단계, `quality`로 결과 점수를 표시합니다.

공통 처리기가 진척도·결과 범위를 검사하고 능력치·성적·저장을 적용합니다. 개발자는 새 모듈에서 완료 조건과 채점·효과를 바꿀 수 있습니다. 미니게임 자체로 완료하는 모듈은 `isComplete`에 해당 조건을 정의하면 공통 완료 경로를 사용합니다. 한 모듈의 코드를 여러 과제가 공유해도 상태는 `task.id`별로 분리됩니다.

그룹과 설정은 과제 발생 시 스냅샷으로 저장합니다. 이후 그룹 설정 변경은 새로 발생하는 과제에 적용합니다. 이번 업데이트에서는 기존 진행 중 과제에 예시 미니게임을 연결하되 이미 쌓은 진척도·완료 과제·성적을 보존합니다. `time_v1`·`contest_v1`은 이전 저장과 기본 결과 계산을 위한 내부 호환 처리기입니다. 플레이 예시 미니게임은 두 종류입니다.
