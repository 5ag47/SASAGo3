# test_hannah 통합 구현 · 2026-11-10

SASAGo3의 기존 8개 브랜치를 비교하고 첨부 DOCX의 스토리·규칙·추가 통합 지시를 반영했다. 브랜치별 기준점과 채택 근거는 [BRANCHES.md](../BRANCHES.md)에 있다. 다른 브랜치는 수정하거나 병합 대상으로 사용하지 않는다.

## 입력과 우선순위

다음 문서의 본문과 표를 실제로 읽어 비교했다.

1. `정과프_프로젝트계획보고서_오은조한나고은규김동연 (1)(1).docx` — 월별 스토리·연애·학사·입시·재화 요구.
2. 같은 이름의 `(2)(1).docx` — 추출 본문은 1번과 동일.
3. 같은 이름의 `(4).docx` — 추가 아이디어, 이벤트/과목/진척도 데이터 구조, 튜토리얼·피로·게임성.
4. 작업 중 추가된 `(3)(1).docx` — 선택 통합, UI 제거 항목, 프리셋·스탯·미니게임·합격/인생 결과. 충돌하는 경우 이 추가 문서의 구체적인 지시를 우선했다.

과거 `docs/integration-2026-11-03.md`와 진단 문서는 그 시점의 기록이다. 이 문서가 이번 브랜치의 동작·검증 기준이다.

## 충돌 해결과 구체화한 선택

- `focus`는 독립 보상값 대신 **건강−스트레스**로 계산한다. 옛 discipline 필드는 이전 저장을 읽기 위해 보존하지만 새 사건의 벌점은 평판 감소로 적용한다.
- ‘1차 전원 합격’과 추가 문서의 ‘1차 탈락·학점 기준’이 충돌하므로 추가 문서 기준을 따른다. 서울대 4.2/4.0/3.8, 카이스트 4.05 기준이며 실제 대학의 입시 기준이 아니다.
- 학점 합산 비율은 문서에서 미정이므로 이전 학점20% + 1학기80%, 이전 학점 범위3.00~4.30으로 정했다. 서버 모드의 실제 초기 학점은 서버가 배정하며 시작 전 화면은 배정 예정으로 표시한다.
- 서울대 재선택 예시는 두 단계 하락하지만 본문은 ‘다음 단계’라고 했다. 구현은 다음 한 단계 하락으로 통일했다. 81~90위는 본문 표에 따라 서울대 선택이 없다.
- 용돈은 본문의 월4주 체계와 기존 엔진을 따라 월 지급한다. 주 지급이라는 하단 초안은 채택하지 않았다.
- 문서의 여러 미니게임 예시는 대안 목록으로 해석했다. 기존 패턴·순서·실험·보고서·배점·카드·기록 면접에 과목별 객관식을 추가했다. 앵그리버드/스도쿠/스네이크/지뢰찾기 등을 각각 모두 복제한 것은 아니다.
- 모든 활동에 새 전용 일러스트를 제작하지는 않았다. 기존 두 캐릭터 그림과 활동 아이콘을 애니메이션으로 사용한다. UI 자동 검사는 DOM 기반이며 픽셀 단위 시각 검사는 완료하지 못했다.
- 자소서 3단계 경로는 기존 자소서 미니게임 경로와 호환되며 최종 피드백 완료 시 공통 자소서 기록을 완성한다. 생활·데이트·청소 같은 반복 작업은 시간 투자 과제로 유지한다.
- Firebase는 codex 브랜치 그대로 **Google 인증**이다. 게임 DB는 공개 서버 D1, 로컬 개발 서버 SQLite다. 문서의 ‘Firebase 데이터베이스’ 표현을 Firestore로 재구현하지 않았다.
- 미제공 ‘지혜의 길잡이’ PDF와 ‘추가 기획 필요’인 휴학 이후 이야기는 생성해 채운 것으로 보고하지 않는다. 기존 휴학 결말은 유지한다.
- 초기 브랜치별 다른 저장 포맷을 합치지 않는다. 연간 엔진의 기존 저장은 migration하고, 다른 포맷/키는 삭제하지 않는다.

## 검증

최종 실행 결과는 아래 기록을 기준으로 한다. CI용 Firebase 공개 설정 모형을 사용한 빌드는 실제 Google 계정 로그인 성공을 뜻하지 않는다.

- 전체 자동 테스트: **281개 통과, 실패 0, 생략 0**. 기존 249개 테스트를 새 규칙에 맞춰 검증하고 캠페인·DOM·서버 회귀 사례를 추가했다.
- `npm run verify`: **통과**. 콘텐츠 21과목·285이벤트·20활동·4특성·10아이템, 모듈 경계·ESLint, 전체 테스트, 서버 전용 빌드, 편집기 빌드, high 기준 의존성 검사를 포함한다. 별도 일반 `npm run build`도 통과.
- 연간 시뮬레이션: 기존 physics 저장 호환 포함 5전공 × 7전략 × 2시드 = 70회. **70회 전부 완주**. [실행별 CSV](test-hannah-balance.csv)에 기록했다. 과제 우선 평균 완료율94.6%, 회복 우선 평균 피로주0·최종 건강94.2, 회복 없는 공부 평균 피로주41·최종 건강0. 모든 실행의 재화 하한0. 이는 크래시·상태 범위·전략 차이 검증이며 전체 입시 경로의 난이도 균형을 입증하지 않는다. 기본 자동 전략의 최고 1학기 GPA는2.61로, 추가 문서의 상위권 학점 기준은 실제 플레이 후 조정 검토가 필요하다.
- npm audit: high 이상 없음. 개발용 ESLint의 minimatch 의존성 경로에서 moderate 4건. 제시된 자동 수정은 ESLint 주요 버전 변경을 요구하므로 강제 적용하지 않았다.
- 실환경 미검증: 브라우저 렌더링/모바일 시각 배치, 실제 Google 로그인, 운영 D1 연결. 이 작업 환경의 브라우저에서 로컬 개발 서버를 열지 못했다. DOM 조작·SQLite·D1 SQL 계약·인증 모형 테스트와 실환경 검증은 구분한다.
- 외부 운영 배포는 하지 않는다. 푸시 대상은 `refs/heads/test_hannah` 하나다.

## 원격 반영 상태

로컬 통합 커밋과 검증은 완료했으나 원격 push는 완료하지 못했다. 명령줄은 GitHub 로그인 없음(`could not read Username`), 연결된 GitHub 쓰기는 `403 Resource not accessible by integration`으로 거부됐다. 따라서 원격 test_hannah를 포함한 8개 브랜치는 기존 SHA 그대로다. 저장소 쓰기 권한이 있는 GitHub 인증 연결이 필요하다. 인증 토큰을 소스나 대화에 넣지 않는다.

전달 ZIP에는 전체 소스, test_hannah의 Git bundle, 이 보고서와 검증 CSV가 포함된다. 인증이 준비되면 동일한 커밋을 test_hannah에만 정상 push하면 된다. 강제 push와 다른 브랜치 병합은 필요하지 않다.
