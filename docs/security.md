# 보안 범위

## 신뢰 경계

브라우저는 신뢰하지 않습니다. 서버는 Firebase가 서명한 Google 로그인 ID 토큰을 검증하고, 검증된 UID에서 HMAC 식별자를 만들어 본인 저장만 조회합니다. 브라우저가 보낸 uid·점수·능력치·전체 저장 파일은 서버 상태를 바꾸는 입력으로 받지 않습니다.

JWT의 서명·알고리즘·aud·iss·exp·iat·auth_time·이메일 인증·Google 제공업체를 검사합니다. Google 계정 조회로 비활성화·폐기 여부도 확인합니다. 공식 검증 요구사항: <https://firebase.google.com/docs/auth/admin/verify-id-tokens>

## 요청과 저장

서버는 승인할 새 명령마다 Web Crypto 난수로 게임 시드를 갱신합니다. 이전 결과에서 내부 난수 상태를 추측해도 다음 요청의 결과를 예측하는 데 재사용할 수 없도록 합니다. 중복·오래된 요청은 새 난수를 뽑거나 결과를 다시 적용하지 않습니다. 시드는 공개 응답에서 숨기며 로컬 엔진의 재현 가능한 테스트는 유지합니다.

- 명령 필드 허용 목록과 도메인 규칙을 각각 검사합니다.
- 요청별 expectedRevision으로 오래된 창의 덮어쓰기를 막습니다.
- idempotencyKey와 명령 해시로 중복 실행·키 재사용을 처리합니다.
- SQLite는 트랜잭션, D1은 조건부 UPDATE와 원자적 batch를 사용합니다.
- Origin·Sec-Fetch-Site·CSRF HMAC, JSON 전용 요청, 8KB 본문 제한, 분당 요청 제한을 적용합니다.
- 응답은 no-store이며 오류에는 요청 ID를 넣습니다. 인증 토큰·이메일·비밀번호를 로그에 쓰지 않습니다.
- 운영 HTTP는 허용하지 않으며 CSP·HSTS·프레임 금지·nosniff 등 헤더를 적용합니다.
- 서버 빌드는 일반 브라우저 저장으로 우회하지 않으며, 저장 파일 업로드 API도 없습니다.

## 파일과 개인정보

`.env.local`, `.local/`, DB, 비밀키는 Git에 올리지 않습니다. 공개 Firebase 웹 설정과 서버의 PLAYER_ID_SECRET은 역할이 다릅니다. 서버 비밀값에 VITE_ 접두사를 붙이면 프런트엔드에 노출될 수 있으므로 금지합니다.

게임 DB에는 HMAC 플레이어 ID와 게임 상태를 저장합니다. 닉네임·캐릭터 외 학교 실명·학번·연락처를 요구하지 않습니다. Firebase는 인증 과정에서 Google 계정 정보를 처리하며, 그 처리는 별도 서비스의 범위입니다.

## 남아 있는 한계

- 로컬 저장 모드는 기록을 가진 사용자의 직접 수정을 막을 수 없습니다.
- 서버 모드도 계정 탈취, 호스트 침해, 브라우저 확장 프로그램, 자동 플레이를 모두 막는다는 보장은 아닙니다.
- 요청 제한은 기본 보호입니다. 공개 운영 규모가 커지면 계정·IP 분산 공격, WAF, 모니터링, 백업·복구, 계정 삭제 정책을 추가로 검토해야 합니다.
- Google 로그인·공개 D1 저장·새로고침 복구를 실제로 확인했습니다. D1의 버전 조건·중복 키 제약도 원격 임시 레코드로 확인했습니다. 대규모 부하·운영 장애 복구·서로 다른 실제 Google 계정 사이 격리는 추가 운영 검증 대상입니다.
- npm audit 결과는 확인 시점에 알려진 취약점만 다룹니다. 0건이 보안 보증은 아닙니다.

## 점검

`PLAYER_ID_SECRET`은 Workers 비밀값으로 등록하고 Git에서 제외된 `.local/cloudflare-player-secret`에 최초 사본을 보관합니다. `npm run cloud:secret`은 기존 원격 키를 교체하지 않습니다. 키를 잃거나 임의 교체하면 기존 HMAC 플레이어와 연결할 수 없으므로 DB와 함께 접근 통제된 백업으로 보관해야 합니다. 값을 채팅·진단 보고서·VITE_ 변수에 넣지 않습니다.

응답 유실은 동일 키로 한 번 재시도합니다. 결과를 확인하지 못하면 최신 저장을 읽기 전 새 명령을 막습니다. 오래된 앱 버전은 새 과목 ID가 포함된 상태를 받거나 명령을 적용하기 전에 갱신 안내를 받습니다. 이는 인증을 대신하는 보안 장치가 아니라 버전 간 호환 보호입니다.

배포 도구는 계정 API와 호환되는 Wrangler 4.131.0으로 고정했고 sharp·undici를 보안 수정 버전으로 올렸습니다. 패키지 변경 후 audit와 실제 배포를 다시 확인합니다.

카드 미니게임은 손패의 유효한 패 ID 또는 고·스톱 명령만 받습니다. 미래의 패 순서는 저장·전송하지 않으며 매 수 서버의 새 난수로 남은 패에서 뽑습니다. 면접도 현재 답변 한 개씩 revision·중복 방지 검사를 거칩니다. 중간 답변을 일괄 답변으로 교체하거나 클라이언트가 점수·승패를 제출할 수 없습니다. 테스트의 사용자 기록은 메모리 DB와 jsdom 저장소를 사용하며 실제 플레이 기록을 초기화하지 않습니다.

`npm test`는 인증 실패, 다른 사용자 기록 접근, 점수 직접 제출, 잘못된 JWT·발급자·프로젝트, 폐기 계정, CSRF·Origin, 중복·동시 요청, 과다 요청과 초기화를 검사합니다. 운영 환경에서는 HTTPS 배포·실제 로그인·재접속·권한 격리까지 다시 확인합니다.
