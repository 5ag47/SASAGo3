# 주간 계획의 순차 실행과 과제 회차

상태: 2026-10-28 사용자 선택으로 채택. ADR-0002의 모듈·그룹 경계를 유지하고 ‘미리 통과한 뒤 시간 배정’ 흐름을 대체한다.

완료한 퍼즐을 나중에 일정에 넣어도 과제가 남는 흐름은 현실의 작업 완료와 맞지 않았다. 각 입력의 서버 왕복을 기다리는 UI도 다음 선택을 지연시켰다.

계획은 7일×3칸으로 먼저 편성한다. advance는 weekRun에 현재 칸·그날·계획·누적 결과를 저장하며 자동 실행한다. 실제 과제 시간, 새 할 일·선택, 다음날 스터디 결과에서 멈춘다. 성공한 회차는 해당 칸의 작업량을 즉시 반영하고 마지막 회차에서 과제를 완료한다. 중간 재접속은 같은 칸·보드를 이어간다. 미래 칸은 편집할 수 있고 지난 칸은 잠근다. 중단은 비용을 보존하고 진척 없이 그 칸을 끝낸다.

과제별 attempts가 누적/주간 횟수·열린 회차·품질·입력 순서를 저장한다. 주간 상한은 선택 설정이다. 몰아서 작업할 자유를 유지하면서 반복 비용·낮은 컨디션의 품질 저하·다음 주 피로가 선택의 대가가 된다. 상한 도달 후 예정된 추가 칸은 휴식으로 바꾼다. 모듈은 도전·실수·실패·성공 효과와 시드 난수를 정의한다.

예측 가능한 카드·칸 선택은 화면에 바로 반영한다. 220ms 묶음 또는 결과 확인 장벽에서 서버로 보낸다. 서버는 회차 ID·입력 sequence·최근 32개 영수증을 검사하며 결과와 진척을 확정한다. 응답 유실·재개 때 같은 입력은 다시 계산하지 않고 불일치는 거절한다. 임시 입력은 사용자/게임/과제/회차별 sessionStorage로 격리한다. 인증·CSRF·revision·원자적 저장·Firebase 폐기 확인은 유지한다.

미니게임 입력의 상태 복사는 변경 가능한 과제·능력치·실행 상태만 깊게 복사하고 불변 기록은 공유한다. 응답은 클라이언트가 요청한 경우 검증된 task-v1 차이만 보내며 baseRevision·revision·콘텐츠 버전을 확인한다. 유실 재전송은 전체 상태로 복구할 수 있다. 서버 시드·숨긴 퍼즐 정답·과거 기록은 차이 응답에 넣지 않는다.

달력은 실제 월간 날짜에 학사 공급자를 표시한다. 게임은 41개 활동 주를 유지하고 실제 월요일과 매핑한다. 미정 요일을 확정 날짜처럼 표시하지 않는다. 날짜 지정 데이터와 실제 전달·마감·평가는 공통 timing을 사용한다. 튜토리얼은 메뉴를 대신 열지 않고 실제 위치를 안내한다.

구버전의 이미 검증된 통과 퍼즐은 한 번만 완료로 옮긴다. 미완료 보드·기존 진척·성적을 보존한다. 현재 버전과 다른 클라이언트의 쓰기는 기존 업데이트 안내로 차단한다.
