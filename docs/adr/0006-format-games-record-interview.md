# ADR-0006: 과제 형식별 미니게임과 서류 기반 면접

- 상태: 채택, 콘텐츠 2026.11.02-2
- 사용자 결정: 과제 내용은 AI가 임의로 늘리지 않는다. 미니게임은 모듈로 등록하고 그룹으로 묶어 지정한다. 실력과 선택이 결과에 보이게 한다.

## 문제

과목 과제 89개가 한 그룹(`order_v2`, 숫자 네 개를 작은 순서대로 고르기)을 썼다. 1년 동안 과제를 할 때마다 같은 화면이 나왔고, 과목 실력과 관계가 없었다. 면접은 고정된 세 질문에 정답이 분명해 두 번째 플레이부터 의미가 없었다.

## 결정

**과제 형식별 미니게임**. `report_v1`(보고서·발표 구성), `experiment_v1`(변인 통제 실험), `sum_v1`(배점 맞추기)을 추가한다. 모두 `puzzleModule`로 보드를 만들고 `makeSessionModule`로 공통 회차·비용·품질 처리를 받는다. `makeSessionModule`의 세 번째 인자로 게임별 설정(`layout`, `variables`)의 검사 함수를 받는다. 과목 이해도(`context.ability`)가 높으면 함정 카드·후보 카드가 줄거나 예비 실험 힌트가 생긴다. 과제 내용 자체는 만들지 않고 보고서의 일반적인 목차·흔한 실수, 실험 조건 이름, 배점 숫자만 쓴다. 실험 조건 이름은 그룹 설정이라 팀이 바꿀 수 있다.

배정은 `data/assignments.json`의 그룹으로 한다. 기존 `subject_game_group`의 89개를 과제 이름에 맞춰 다섯 그룹으로 나누고, 맞는 형식이 없는 도시계획 주간 과제와 비커 시각화는 남긴다. 그룹 설정은 과제가 발생할 때 스냅샷으로 저장되므로 이미 생긴 과제는 그대로다.

**서류 기반 면접**. 면접을 시작할 때 `interviewSpec(state)`가 세 질문의 근거를 만들어 `minigames.interview.questions`에 고정한다.

1. 기록: 완료한 전공 과제(없으면 다른 과목 과제, 졸업논문 순)와 그 작업 품질.
2. 전공 제시문: 첫 전공 과목의 과목 실력.
3. 학교생활: 단체방 사건에서 실제로 한 선택, 스터디·모의면접 참여, 면접 연습 횟수.

선택지는 세 개로 같지만 점수는 근거에 따라 달라진다. 잘 해낸 과제는 구체적으로 설명할 때, 품질이 낮은 과제는 부족함을 인정할 때 가장 높다. 다만 기록이 약하면 어떤 답도 높지 않다(인정은 손해를 줄일 뿐이다). 기록과 다른 경험을 말하면 낮다. 점수 = 답변 평균×65 + 구술력×0.25 + 면접 연습(1회 0.5, 최대 10), 최대 100이다. 시뮬레이터는 `bestInterviewAnswers`로 자기 기록을 아는 학생처럼 답한다.

## 이전 저장

질문이 없는 면접 기록(2026.10 방식)은 그대로 유효하고, 화면은 예전 고정 질문으로 검토를 보여 준다. 저장 변환은 필요 없다. 진행 중이던 과제의 미니게임과 확정된 성적은 바꾸지 않는다.

## 검증과 한계

`tests/domain/school-games.test.js`가 세 게임의 정답·실수·실력에 따른 난이도·숨김 정보·설정 검사와 실제 주간 실행을 확인한다. `tests/domain/interview-record.test.js`가 기록에 따른 최선의 답, 기록과 다른 이야기의 감점, 질문 고정, 빈 기록의 상한, 전공 과제 우선, 이전 기록 호환을 확인한다. 실제 화면에서 세 게임의 입력·저장과 면접 질문 표시를 확인했다. 반복 플레이에서의 재미와 난이도 체감은 사람이 직접 해 봐야 안다. 보고서 목차와 실수 카드, 실험 조건 이름은 일반적인 예시이며 과목별 실제 수행평가 기준은 아니다.
