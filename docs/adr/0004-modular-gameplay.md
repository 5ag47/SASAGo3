# ADR-0004: 기능별 명령·저장·패널과 누적 기록을 쓰는 입시

- 상태: 채택, 콘텐츠 2026.10.28-3
- 사용자 결정: 분기는 공통 단계에서 일부 합치되 이전 선택의 대가는 남긴다. 학점과 생기부가 중심이며 논문은 여러 활동 중 하나다. 교사 관계는 보조한다. 기록에 대한 부정적 판단을 대사로 설명하지 않고 준비 과정의 부담으로 느끼게 한다.

## 구조

`engine.js`는 검증·복사·명령 전달·revision·사후 검증만 맡긴다. `commands/`의 기능별 정의가 허용 요청 필드와 행동 규칙을 함께 소유한다. 서버도 이 등록부에서 필드 목록을 얻어 UI/API/규칙의 중복 목록을 줄인다. 명령 ID 충돌·빠진 계약은 시작 때 거절한다. 인증·CAS·중복 방지·응답 투영은 서버의 책임으로 유지한다.

`state.js`는 기존 import를 보존하는 진입점이고 `state/{base,migrate,validate}.js`가 생성·이전 저장 변환·불변조건을 나눈다. 변환 단계는 안정된 이름을 가지고 순서대로 실행한다. 단계 실패는 `migrationId`를 남기며 전체 저장을 수정하지 않는다. 변환은 여러 번 실행해도 같은 결과여야 한다.

화면 조립은 `panels/{planning,school,narrative,system}.jsx`로 분리하고 이름·너비는 navigation에 모은다. UI는 상태를 읽고 명령만 요청한다. 공통 게임 테마는 유지한다. 의존성 검사에는 누락된 상대 import와 순환 참조를 추가한다.

과제와 달력 편집은 `content-edits.js`의 항목 비교·충돌 판정과 `content-files.mjs`의 잠금·검증·백업·임시 쓰기·교체를 공유한다. 형식별 검증은 어댑터로 분리한다. 다른 ID는 합치고 같은 ID가 변경됐으면 전체 적용을 거절한다. 이 도구는 플레이어 DB에 접근하지 않는다.

## 공통 단계와 누적 결과

원서 시즌은 지원 방향 3개와 공통 제출·면접·평가 단계로 제한한다. 준비한 활동과 능력치를 매 분기마다 별도 시나리오로 복제하지 않는다. `when` 조건은 이전 선택·과목·능력치 등을 제한된 JSON 규칙으로 조회한다. 실행 코드를 JSON에 넣지 않는다.

학점·교과 수행·탐구·협업·지속성을 실제 기록에서 계산한다. 형식을 지정하지 않은 기존 교과 과제도 탐구 기여를 가지며 논문만 탐구를 채우는 구조를 피한다. 종합 전형은 학점+생기부 비중을 65~70%로 두고 전공 연계·자소서·추천서·면접을 보조로 둔다. 선택만으로 점수를 주던 지원 방향 보너스는 없앤다. 방향은 지원할 전형의 묶음이며 제출 전 전환은 스트레스 2를 쓰고 이전 준비를 보존한다.

자소서 도전에는 `support: "essay"`를 명시한다. 공통 호스트가 기록과 관계에 따른 비용·품질을 적용하고 진척 예상과 실제 작업은 같은 함수를 쓴다. 추천서는 기존 교사 선택 후 해당 교사의 실제 상담 시간에 자료를 확인하고 다음 게임 날 검토 결과를 받는다. 기본 두 번의 상담이 필요하며 필요 횟수는 시작할 때 저장한다.

기록·관계는 비용에 선형으로 반영한다. 비슷한 준비는 비슷한 부담을 갖는다. ‘기록이 나쁘므로 거절’ 같은 평가 문구나 내부 부담 수치를 HUD에 내보내지 않는다. 진행 단계·소비한 능력치·실제 완료 기록은 확인할 수 있다. 검사에는 인접한 기록/친밀도의 차이가 큰 비용 점프를 만들지 않는 사례를 포함한다.

자소서·서류 점검·지원 방향과 선택한 추천서가 준비되면 서류를 한 번 제출한다. `documents`는 당시 학점·기록·전공 연계·자소서·추천서를 고정한다. 이후 면접 준비는 면접 평가에 계속 영향을 준다. 지원하지 않은 전형은 미지원으로 남기며 불합격 스트레스나 추첨을 적용하지 않는다.

## 이전 저장과 검증 한계

이전 저장의 선택한 추천서는 준비 완료로 변환해 다시 상담을 요구하지 않는다. 이전에 끝낸 과제·성적·입시 결과는 다시 계산하지 않는다. 이미 서류와 자소서가 끝난 저장은 현재 보존된 자료로 제출 기록을 한 번 만든다. 과거 실제 제출 날짜의 자료를 복원할 수 있다는 의미는 아니다. 이전 클라이언트는 콘텐츠 버전 불일치로 갱신을 요구한다.

게임용 입시 모델이며 실제 입시의 예측식이 아니다. 시뮬레이션·자동 검사는 규칙과 회귀를 검증한다. 간접적인 부담의 체감, 초보자 이해도와 재미는 별도 실제 플레이 관찰이 필요하다. 이 결정은 무충돌 협업이나 완전한 보안을 보장하지 않는다.
