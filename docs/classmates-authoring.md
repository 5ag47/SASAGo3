# 동기·소문·교내 원서 현황 편집

동기 친구들, 주차별 소문, 교내 원서 현황, 친구들의 결과는 모두 `data/classmates.json` 한 파일에 있습니다. 코드를 고치지 않고 이 파일만 바꾸면 됩니다. 현재 내용(6명·소문 20개)은 게임용으로 만든 가상 인물과 이야기이며, 팀이 자유롭게 바꿔도 됩니다.

## 수정 절차

1. `data/classmates.json`을 엽니다.
2. 아래 형식대로 고칩니다.
3. 프로젝트 폴더에서 `npm run check`를 실행합니다. 잘못된 곳이 있으면 `classmates.seoyun.rumors[2].week: 0~40 정수`처럼 고칠 위치와 이유를 알려 줍니다.
4. `npm run play`로 게임을 열어 확인합니다.

## 학교 설정 (`school`)

| 항목              | 뜻                                                                      | 예                        |
| ----------------- | ----------------------------------------------------------------------- | ------------------------- |
| `boardWeek`       | 진학실에 교내 원서 현황을 보여 주기 시작하는 주 (0~40)                  | `25`                      |
| `resultWeek`      | 친구들의 결과를 알리고 진학실에 보여 주는 주 (0~40)                     | `38`                      |
| `otherApplicants` | 이름 없는 다른 학생들의 전형별 지원자 수. 표의 인원 = 이 수 + 친구 + 나 | `{ "kaist_postech": 23 }` |

전형 ID: `top_interview`(서울대 종합), `kaist_postech`(카이스트·포스텍 종합), `korea_university`(고대 종합), `essay`(연논 논술), `regular`(정시).

## 친구 한 명 (`classmates.<ID>`)

```json
"seoyun": {
  "name": "서윤",
  "relation": "룸메이트",
  "major": "chemistry",
  "profile": "실험 노트를 날짜별로 정리해 두는 사람. 말수는 적다.",
  "routes": ["kaist_postech", "korea_university"],
  "result": { "accepted": true, "text": "카이스트·포스텍 합격. 기숙사 짐을 제일 먼저 쌌다." },
  "rumors": []
}
```

| 항목       | 규칙                                                                                  |
| ---------- | ------------------------------------------------------------------------------------- |
| ID         | 영어 소문자로 시작하는 2~40자. 한 번 정한 ID는 바꾸거나 다른 친구에게 재사용하지 않음 |
| `name`     | 1~10자                                                                                |
| `relation` | 1~10자. 이름 옆에 작게 표시 (룸메이트, 같은 반, 스터디장 등)                          |
| `major`    | `math`, `physics`, `chemistry`, `biology`, `information` 중 하나                      |
| `profile`  | 1~60자 한 줄 소개. 진학실 친구 목록에 표시                                            |
| `routes`   | 이 친구가 지원하는 전형 ID 목록. 교내 원서 현황 표에 이름이 들어감                    |
| `result`   | `accepted`(합격 여부)와 `text`(1~80자). `resultWeek`부터 진학실·한 해 결산에 표시     |
| `enabled`  | 선택. `false`면 지우지 않고 잠시 빼 둠                                                |

친구를 지울 때는 `"enabled": false`를 먼저 권합니다. 이미 받은 소문 기록과 ID가 어긋나지 않습니다.

## 소문 (`rumors` 배열의 한 항목)

```json
{
  "id": "seoyun-essay",
  "week": 26,
  "text": "서윤이가 자소서 3차 수정본을 담임 선생님께 보여 드렸대.",
  "when": { "task": "essay", "status": "active" },
  "effect": { "stress": 2 }
}
```

| 항목     | 규칙                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------ |
| `id`     | 영어 소문자로 시작하는 고유 ID. 모든 친구의 소문 사이에서 겹치면 안 됨. 바꾸거나 재사용하지 않음 |
| `week`   | 이 소문이 도착하는 주 (0~40). 그 주가 시작될 때 알림 종에 "소문"으로 들어옴                      |
| `text`   | 1~120자                                                                                          |
| `when`   | 선택. 이벤트와 같은 조건 문법. 그 주에 조건이 맞지 않으면 이후에도 나오지 않음                   |
| `effect` | 선택. 능력치별 -10~10. 소문을 들은 순간 적용 (예: 남이 앞서가면 스트레스 +2)                     |

자주 쓰는 조건:

- 내 과제가 진행 중일 때: `{ "task": "essay", "status": "active" }`
- 특정 과목 수강생에게만: `{ "course": "general_biology" }`
- 여름 상담을 받았을 때: `{ "flag": "counseled", "equals": true }`
- 스트레스가 높을 때: `{ "stat": "stress", "min": 60 }`
- 여러 조건: `{ "all": [ … ] }`, `{ "any": [ … ] }`, `{ "not": … }`

전체 조건 문법은 [게임 확장 안내](gameplay-extension.md)를 보세요.

## 규칙과 한계

- 소문은 난수를 쓰지 않습니다. 같은 선택이면 같은 소문이 같은 주에 옵니다. 그래서 밸런스 비교 결과를 흔들지 않습니다.
- 소문 효과는 작게 둡니다(-10~10). 친구 소식이 내 점수를 직접 바꾸지는 않습니다. 친구의 지원은 내 합격 기준에 영향을 주지 않습니다.
- 이미 받은 소문은 `flags.rumors`에 ID로 기록됩니다. 소문의 주를 앞당기거나 문구를 고치면 새 게임과 아직 그 주에 도달하지 않은 게임에만 반영됩니다.
- 코드 위치: 규칙 `src/domain/classmates.js`, 화면 `src/features/year-game/ClassmatesPanel.jsx`, 검사 `tests/domain/classmates.test.js`.
