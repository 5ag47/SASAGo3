# 구조와 개발 경계

게임의 흐름은 `UI → 명령 → 검증 → 상태 전이 → 저장 → 새 화면`입니다. 새 화면은 상태를 읽고 명령을 요청합니다. UI에서 능력치·과제 진척을 직접 수정하지 않습니다.

```text
data/                        과목·활동·이벤트·아이템·특성의 정적 정의
src/domain/                  React·DOM·네트워크에 의존하지 않는 순수 게임 규칙
  catalog.js                 데이터 연결과 달력·표시용 정의 (수학·물리 별도 전공)
  state.js                   저장 형식과 상태 검증
  engine.js                  명령 처리의 단일 진입점 transition(state, command)
  week.js                    21칸 순차 실행, 생활 부담·피로·시험
  tasks.js                   과제 진행·완료·마감
  events.js / choices.js     이벤트 발생·선택
  card-game.js / interview.js 카드 진행 규칙·면접 문항
  minigames.js               미니게임 저장 검증·기한 종료
  grades.js / random.js      학점·입시 / 저장되는 난수 시드
src/features/year-game/      화면과 기능별 React 컴포넌트
src/App.jsx                  현재 게임 진입점 (LegacyApp.jsx는 이전 초안 보관)
src/platform/                브라우저 저장·Firebase·서버 통신·진단
server/                      인증·요청 보안·원자적 상태 저장
tests/domain/                다섯 전공 완주 및 게임 규칙 회귀 검증
tests/server/                접근 격리·JWT·변조·동시성·중복 요청 검증
```

## 명령 계약

`create`, `plan`, `copy_day`, `preset`, `elective`, `choose`, `advance`, `buy`, `ending`을 지원합니다. 명령은 클라이언트가 원하는 **행동**이고, 결과 상태는 엔진이 결정합니다. 엔진은 원본을 바꾸지 않으며 새 revision을 반환합니다. 검증 실패 시 전체 변경을 적용하지 않습니다.

서버 API는 `{command, expectedRevision, idempotencyKey}`만 받습니다. uid·점수·능력치·전체 저장을 제출하는 필드는 거부합니다. Firebase 서명 검증으로 얻은 uid만 플레이어를 구분하는 데 사용합니다. 튜토리얼 순서로 조작을 잠그지 않으며, 선택 이벤트는 마감까지 응답할 수 있습니다. 미응답은 마감 시 미참여로 기록합니다.

## 데이터와 플레이 기록 분리

`data/*.json`은 안정된 ID를 키로 가진 객체입니다. 팀원이 새 이벤트를 추가할 때 기존 ID를 바꾸지 않습니다. 이벤트에 과목 조건이 있으면 그 과목 수강자에게만 발생합니다. 사용자 진행도는 정적 JSON에 쓰지 않습니다.

로컬 저장 키는 `sasago3-year-v1`입니다. 예전 `sasago3-save-v1`과 기존 React 초안은 그대로 보존했습니다. 서로 다른 진행 규칙을 사용하는 저장을 무리하게 변환하지 않습니다. 직전 저장은 `sasago3-year-v1-backup`에 보관합니다.

로컬에서는 Web Locks로 같은 출처의 창끼리 저장을 직렬화하고 revision으로 덮어쓰기를 차단합니다. Web Locks를 지원하지 않는 환경에서는 revision 검사가 남지만 완전한 동시 쓰기 방지는 보장하지 못합니다. 서버 모드는 DB 트랜잭션/CAS로 강제합니다.

## 규칙 요약

- 겨울 1주 + 3~12월 월 4주 = 41주. 7일 × 아침·1자·2자 = 21칸입니다. 초기 기획의 하루 두 칸은 추가 요청에 따라 세 칸으로 조정했습니다.
- 기본 스트레스 +6, 학습 칸당 약 0.35 추가. 정규수업·생활 피로는 체력 -8·집중력 -3입니다.
- 학습 효율은 집중력, 체력 30 미만, 스트레스 70 이상, 피로 상태, 방학 환경, 활동 반복을 반영합니다. 높은 능력치는 성장 폭이 줄어듭니다.
- 체력 25 미만 또는 스트레스 80 이상으로 주를 마치면 다음 주 만성피로, 학습 효율 ×0.65입니다.
- 완료 과제에 다시 배정된 시간, 진행할 졸논·자소서가 없는 시간, 가입 전 스터디는 호실 휴식으로 바꾸고 결과에 이유를 남깁니다. 이미 끝난 과제 보상을 중복 지급하지 않습니다.
- 과제는 마지막 배정까지 처리한 뒤 마감 판정합니다. 퀴즈·시험은 해당 주의 활동을 마친 실력으로 평가합니다.
- 퀴즈 20%, 중간 30%, 기말 30%, 수행 20%. 실시된 항목만 있는 기간에는 잠정 성적을 표시합니다. 학점은 과목별 학점 수로 가중 평균합니다.
- 입시 공식은 실제 대학 기준이 아닌 게임용 가상 규칙입니다. UI에서 준비도와 미제출 조건을 공개합니다.

## 무작위와 재현

`course-progress.js`는 과목별 이해도를 관리합니다. 자습·과제를 수행한 과목만 이해도가 증가하고 시험 실력에 공통 능력 65%와 이해도 35%를 반영합니다. 기존 성적은 바꾸지 않고 기존 저장에 이해도를 추가합니다.

`schedule.js`는 고정 학원·행사 시간 예약을, `school-calendar.js`는 달력과 실제 시험의 공통 일정을, `planning.js`는 과제 배정 칸 수와 주간 검토를 관리합니다. 빠른 편성은 고정 칸에 가려지는 과제 시간을 배정한 것으로 세지 않습니다.

`copy_day`는 원본 요일과 받을 요일 배열을 받습니다. 원본·대상 중 어느 쪽이든 고정된 시간대는 건너뛰고, 나머지 칸을 하나의 revision으로 저장합니다. 일요일도 대상에 포함됩니다. 개별 신청·프리셋·복사는 같은 실습 기록 함수를 사용합니다.

면접과 카드는 `minigames`에 중간 진행을 저장합니다. `choose` 한 번마다 답변 또는 카드 한 수만 적용하며, 완료 시 한 번만 결과를 기록합니다. 창 닫기는 게임 결과에 영향을 주지 않습니다. 마감 주를 넘기면 미완료 기록을 중단 상태로 남기고 다음 주로 진행합니다. 자세한 계약은 [미니게임 확장](minigames.md)을 참고합니다.

`random.js`만 난수를 사용합니다. 시드는 저장에 포함되며 주간 기록에 이전/이후 시드를 남깁니다. 같은 상태와 명령은 같은 결과를 냅니다. 서버는 시드를 응답에 공개하지 않습니다.

공개 서버는 새로 승인할 명령마다 Web Crypto로 시드를 갱신한 상태를 엔진에 전달합니다. 직전 요청의 내부 상태에서 다음 결과를 예측하지 못하도록 하며, 중복·오래된 요청은 재추첨하지 않습니다. 도메인 단위의 재현 가능한 테스트와 서버의 새 난수 공급을 분리합니다.

로컬 진단 보고서는 닉네임을 가리고 최근 200개 이벤트, 명령·revision·주차·능력치/과목 변화·버전, 현재 상태와 주간 기록을 포함합니다. 탭의 sessionStorage에 진단을 보관해 새로고침 동안 유지합니다. 탭을 닫으면 브라우저 정책에 따라 사라질 수 있습니다. 서버 진단은 요청 ID와 서버의 구조화 로그를 함께 확인합니다. 내부 오류의 코드 위치는 서버 로그에만 남깁니다. 로그에 인증 토큰·이메일·비밀번호를 넣지 않습니다.

일정 명령에는 실제 바뀐 칸의 이전·이후 활동과 대상을 남깁니다. 미니게임 명령에는 전후 단계·턴·점수·답변 개수를 기록합니다. 요약 생성은 `platform/command-log.js`로 분리되어 화면 코드가 로그 형식을 직접 만들지 않습니다.

`api-transport.js`는 응답 유실·일시 오류에서 같은 명령 본문과 중복 방지 키로 한 번 재시도합니다. 결과를 계속 확인하지 못하면 새 명령을 막고 최신 저장을 읽도록 합니다. 읽기와 초기화·로그아웃도 동시에 실행되지 않도록 조정합니다.

튜토리얼의 화면 확인 기록은 계정과 게임 시작 revision의 해시로 구분합니다. 단원 버튼을 눌렀다는 이유만으로 실습 완료를 주지 않습니다. 방문 기록은 UI 안내에만 사용하며 서버 보상에 영향을 주지 않습니다.
